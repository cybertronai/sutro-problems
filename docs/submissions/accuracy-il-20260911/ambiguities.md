# Ambiguities and remaining work

This report separates resolved display/scoring issues from decisions needed before treating the MLP experiments as new benchmark submissions.

| Issue | Finding and implication |
| --- | --- |
| Mixed units and excess digits | Fixed in the MNIST README and current results report: time uses ps, energy uses fJ, and performance displays use two significant figures. Historical session messages and raw machine-readable evidence retain their original wording and precision. |
| Rounded percentages near a target | A displayed mean of 65% can be slightly below 65% before rounding. Eligibility must use exact counts: 390/600 is required for 65%. Each seed's count is published. |
| Raising the accuracy requirement | A 60% target was met by every seed at 300 epochs and above in this experiment. A 65% target was met by one of 15 runs; 70% and 75% were not reached. These observations justify further evaluation, not a universal ceiling or an automatic rules change. The official 50% requirement is unchanged. |
| Public test-set reuse | The canonical test set is public and was used by the previous 1NN attempt. Within this study, selection used a training-only split, all configurations/seeds were frozen, and all predictions were saved before its test evaluation. This does not create a new unseen test set. Further tuning after these results should use new independent validation before claiming a stronger submission. |
| Validation search adaptivity | The second search grid was declared after observing the first grid's training-validation results, before test evaluation. Both grids and their chronology are preserved. Calling the entire search preregistered would overstate the protocol. |
| Intermediate-language acceptance | The affine-loop representation is a submission-owned prototype, not an officially accepted format. Its ordinary v4 leaves, fixed placement, exact address histograms, and expansion semantics are inspectable. The benchmark still needs to decide which compact representations and validators it will accept. |
| Cost scoring versus semantic verification | A fast static score establishes instruction/access costs for the represented program. It does not establish learning correctness or the absence of hardcoded answers. Small expanded end-to-end tests, full ordered numerical training, prediction hashes, and source review provide separate evidence. The largest MLP trace was not individually interpreted. |
| Scoring-time scope | The new timing includes structural validation, initialization proof, placement, histograms, integer sums, and hashing. It excludes program loading, file output, numerical execution, and accuracy checks. The old 1NN interpreter performed numerical execution too; dividing these times is not an equal-work end-to-end speedup. |
| Restricted control and addressing | Fixed bounds and affine addresses make aggregation possible. Data-dependent iteration, indirect addressing, mutable placement, and deallocation are unsupported. Valid programs can be rejected if initialization proof exceeds its budget. The current scorer is not a general-purpose verifier for arbitrary algorithms. |
| Arithmetic and comparison contract | The experiment declares FP32 round-to-nearest after separate multiply/add instructions, ascending reductions, raw-word copies/selections, and explicit comparison predicates. Labels are raw uint32 words and equality compares their FP32 interpretations; this assumes preserved subnormals. GPU compilation would need to preserve or explicitly account for these conventions, including avoiding unintended FMA or flush-to-zero changes. |
| Initialization and compilation boundary | Initial weights depend only on declared architecture and seed, so their literal bits are compiled into the IL; all writes are charged. Input transformation, one-hot targets, complete training, and inference are also represented. Whether seed generation itself must be runtime work should be specified consistently for submissions; no learned values are compiled into this program. |
| Area convention | The reported area is one µm² per occupied word at the fixed half-diamond placement. It includes all explicitly initialized buffers, labels, targets, and test images. A containing footprint or technology-specific chip area would be a different measure. |
| Actual hardware measurements | Only the original 1NN has A100 runtime and idle-adjusted NVML energy. New MLP CPU training times are contextual measurements and have slightly different setup boundaries from model scores. No MLP A100 time or energy is inferred from them. A GPU implementation, numerical checks, and repeated NVML trials are required for complete new submissions. |
| Energy and time relationship | Uniform ps and fJ remove unit-conversion friction. Energy still depends on power: E(fJ) = 1000 × P(W) × t(ps). Model costs and measured idle-adjusted energy are distinct quantities even when displayed on the same unit scale. |

The practical next candidate is H32 / 300 epochs, which exceeded 60% with all three fixed seeds and is much cheaper in the model than the longer training runs. A complete submission would fix its seed without selecting on these test results, validate the chosen compact-format policy, and measure an equivalent A100 implementation. A stronger accuracy target needs additional evidence.
