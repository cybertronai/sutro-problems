# MNIST-small: potential ambiguities and problems

> **Accuracy scope:** The current small/medium requirement is mean ± sample SD over 11 independently resampled datasets. This report preserves a historical single-dataset evaluation; its per-draw threshold checks do not establish that aggregate. [Current accuracy protocol](https://github.com/cybertronai/sutro-problems/blob/main/mnist/instructions.md#accuracy-over-11-random-datasets).

Audit date: 2026-09-10 (local time). This audit examined Sutro rules/code at `e70f9c9e1db65b62d9256f7b1f9b668cf4c48909` and the computation-model specification at `26abcca402de647381d31286d42dfbb7a001763d`. Severity measures the effect on validity or comparison, not whether an honest, explicitly qualified submission can proceed.

## Open issues

1. **High — No canonical tape serialization.** The task provides float32 image arrays and int64 label arrays, while the machine consumes sequential 32-bit words. The task does not fix the order of train images, train labels and test images, the representation of labels, or whether preprocessing/repacking belongs to the scored algorithm. The model explicitly requires the workload to fix one input stream for all solutions. Order matters: an interleaved image/label stream can reduce scratch storage relative to all images followed by all labels. A submission should specify its complete stream order, binary encoding, word count and output encoding, consume each input word once, and identify this as a proposed convention requiring organizer agreement. Sources: [input contract](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L148-L179), [fixed stream requirement](https://github.com/cybertronai/simplified-dally-model/blob/26abcca402de647381d31286d42dfbb7a001763d/models/single-core-with-tape/README.md#L90-L113).

2. **High — Arithmetic representation is incomplete.** The model specifies 32-bit words; v4 gives arithmetic formulas and calls `set` literals integers, but does not specify IEEE float32 arithmetic, integer signedness/overflow, rounding, division exceptional cases, or typed comparisons. MNIST inputs are float32. A float32 implementation therefore needs an explicit numerical convention, including rounding after each primitive and whether GPU fused multiply-add is allowed. Input-dependent host computations must not be silently substituted for missing ISA operations. The operation list also has no branch, indirect load, square root or exponential; a fixed, unrolled generator using listed primitives is easier to audit than a score for an unspecified high-level program. Source: [v4 notation and complete instruction table](https://github.com/cybertronai/simplified-dally-model/blob/26abcca402de647381d31286d42dfbb7a001763d/instruction-sets/v4/README.md#L9-L36).

3. **High — The accuracy evaluator does not authenticate the tier or dataset.** `--tier small` selects a filename; the evaluator reads only that file's `test_labels`. It does not check the canonical profile, 600-example size, source indices or array hashes. An isolated audit fixture with a one-label `small.npz` was accepted and reported `tier=small, correct=1, total=1, accuracy=1.0`. This does not invalidate the real dataset, but the evaluator's output alone cannot establish a valid MNIST-small submission. Submissions should verify canonical array hashes and shapes separately and retain that result with the score. Source: [evaluator loading/scoring](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/code/evaluate.py#L80-L91).

4. **Medium — “Area from peak memory” lacks a full definition.** The workload does not say whether Area means maximum live words, total allocated addresses, occupied cells or the enclosing physical footprint, and whether tape, instruction storage or control state is included. The machine requires a fixed address-to-coordinate mapping and has 1 µm grid spacing, but no area formula. Report peak allocated scratch words and bytes, all allocated coordinates, occupied-cell area under an explicitly stated convention, and the bounding dimensions if useful. Do not silently call an occupied-cell count the complete chip area. Sources: [requested metric](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L19-L29), [geometry and allocation](https://github.com/cybertronai/simplified-dally-model/blob/26abcca402de647381d31286d42dfbb7a001763d/models/single-core-with-tape/README.md#L12-L31).

5. **Medium — Scoring boundaries need a submission-level convention.** Training plus inference is explicitly required; inference-only timing is not a reasonable interpretation. The rules do not fully define whether hyperparameter search, validation/refitting, input conversion, compilation, score-trace generation or score verification is included in the leaderboard metrics. “Time to score” is the runtime of model-score calculations, distinct from classification evaluation and modeled execution time. Report one fresh final training-plus-inference execution and disclose tuning/selection separately; state exactly what the score timer includes. Sources: [score timing definition](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L19-L29), [training requirement](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L31-L53).

6. **Medium — A100 energy/timing protocol is underspecified.** The rules require A100, Triton or pyptx, and NVML idle-adjusted joules, but give no timing boundary, repetition count, idle sampling interval, integration procedure, warmup policy, clock/power policy or uncertainty requirement. For a short workload, one power sample or one kernel's runtime is insufficient to substantiate a precise energy number. Specify GPU variant and versions; synchronize timings; repeat complete training-plus-inference workloads; retain measured energy or power observations and idle baseline; state whether transfers, launches and compilation are included. If measurements are unavailable, use the explicitly allowed em dash and mark the submission incomplete for the hardware requirement. Source: [reporting and hardware requirements](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L13-L29).

7. **Medium — Public test labels mean process integrity is not enforced.** Rules explicitly prohibit learner access to test labels and require training-only selection, but those labels and source indices are distributed openly; the evaluator cannot detect test-set tuning or lookup. Large-tier training includes the original examples used as small/medium tests, so cross-tier access matters. Keep the learner input restricted to the three authorized arrays, freeze model/hyperparameters before the final test evaluation, retain the selection log, and clearly separate any pretrained or cross-tier experiment. This is a known limitation of an open benchmark, not evidence of leakage by this submission. Source: [learning and selection contract](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L161-L168).

8. **Low — Rules are mutable and acceptance is not automated.** The pinned rules used a 50% threshold; the current small requirement is 60%, and model links target mutable `main`. Pin both source revisions and state the target in the report. An accuracy JSON is not a certification of tape/ISA, model-score or hardware compliance. Source: [threshold and model links](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/README.md#L3-L25).

9. **Medium — Canonical pixel hashes may depend on the numerical backend.** The resize implementation calculates float32 weights and performs two `np.matmul` reductions. The exact geometric overlap is defined, but floating-point reduction order is not fixed by the source. Different BLAS libraries, CPU instruction choices or NumPy builds can therefore potentially produce different low bits and fail the strict pixel-content hashes despite applying the same mathematical resize. This is a concrete portability risk in the source arithmetic, **not an observed cross-platform mismatch in this attempt**. Preserve the verified canonical arrays or pin the tested numerical environment; if a reproduced hash differs, investigate before treating it as the canonical dataset. Sources: [float32 overlap weights and matrix reductions](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/code/data.py#L131-L156), [exact content hashing](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/code/data.py#L172-L175).

## Submission-specific evidence and limitations

- The candidate was fixed **1-nearest-neighbor with ordered float32 squared Euclidean distance and first-training-row tie breaking**, selected before final test scoring. Its one training-only sanity check used a deterministic 480/120 split, scoring **63/120 (52.50%)**. No alternative candidate or hyperparameter search is reported. Code inspection can establish what the submitted program does; the session chronology is the evidence for when the candidate was fixed.
- Final test accuracy was **308/600 (51%)**, just **eight correct predictions above the original 300/600 threshold**. It passed that historical fixed-dataset target, but is below the per-draw 360/600 diagnostic threshold. It is one dataset and one fixed split: it does not measure variation across resampled datasets or establish a robust margin above 50% in a broader population.
- The learner validates shape, dtype and canonical SHA-256 for all **three allowed learner arrays** before prediction. It accesses no `test_labels` array or source-index arrays. A separate audit verified all **six** canonical arrays, including source indices and test-label bytes for integrity only; its all-six check should be retained with the submission.
- The CPU reference materializes a 600 × 600 distance matrix; it is an algorithmic reference. Its measured wall time and peak memory must not be presented as the tape machine metrics of a separate streaming implementation. The final report must identify the scored tape program and the measured A100 implementation separately.

## Questions resolved by the existing rules

- The canonical small dataset is **600 train / 600 test, 3 × 3, `competition-v2`, seed 20260910**, sampled without replacement from the official training pool. The historical 1,000/1,000 CNN results are explicitly a different dataset. Sampling, normalization and fractional box-area resizing are documented. [Dataset preparation](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L95-L136).
- The local canonical `mnist/data/small.npz` checked in this audit has all six expected array shapes, no train/test source-index overlap, and **all six array-content SHA-256 hashes match the published manifest**. The hashes, unlike compressed NPZ container hashes, are independent of ZIP metadata. No dataset mismatch was observed. [Canonical manifest](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/doc/dataset_manifest.json), [array-hash definition](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/code/data.py#L172-L175).
- No neural network architecture is required. Training and inference are both in scope. Unlabeled test images are available, but test-label-based model selection is disallowed. [Task and learning scope](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L31-L53), [selection policy](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L161-L168).
- Use **model 2**, not the older read-only-distance model. Non-tape reads and writes are charged, each operand occurrence counts, `select` reads both alternatives, and source reads precede overwrites. `recv` and `send` cost zero in the model, including their scratch accesses; this is an accounting exclusion, not physical free I/O. The per-access floors are maxima, not additive surcharges. [Authoritative cost rules](https://github.com/cybertronai/simplified-dally-model/blob/26abcca402de647381d31286d42dfbb7a001763d/models/single-core-with-tape/README.md#L33-L113).
- Submission placement is already specified: `mnist/submissions/<name>/`, with reproduction sources, a standalone report and a results-table row, submitted through a pull request. A new top-level submissions directory is unnecessary. [Submission instructions](https://github.com/cybertronai/sutro-problems/blob/e70f9c9e1db65b62d9256f7b1f9b668cf4c48909/mnist/instructions.md#L5-L17).

## Blocker assessment

The identified rule gaps do not prevent producing and publishing an honest attempt under explicit conventions. They do prevent claiming fully standardized comparability or official acceptance without organizer confirmation. The observed 308/600 passed the original accuracy requirement but does not pass the current 60% requirement. Missing measured A100 runtime/energy would leave the hardware portion incomplete even though the reporting rules permit em dashes; the final measurement artifacts must establish whether that portion was completed.

## Problems encountered and limitations of this attempt

The fixed 1NN attempt scored **308/600 (51%)**, eight predictions above its original 50% threshold. It is below the current 60% requirement by 52 predictions. Its mean measured whole-task A100 graph throughput is **0.0069 ms** and paired-idle NVML energy is **0.52 mJ**. These are completed measurements, replacing any hypothetical hardware blocker discussed above.

- **GPU setup failures, resolved:** the pinned base image lacked a C compiler; nested Triton code needed a module-global language alias; Modal did not provide its package metadata inside the container. Three initial launches failed before measured energy trials. Adding gcc and fixing import/metadata handling resolved them. All three measured trials from the successful run are retained.
- **Energy precision, unresolved:** before/after idle baselines drifted from approximately 64 to 83 W. Per-trial paired-baseline energy spans 0.48–0.55 mJ per task; using before-only or after-only baselines yields 0.47–0.60 mJ. This sensitivity is not a confidence interval. A headline value near 0.52 mJ is more defensible than many significant digits.
- **Timing boundary, disclosed:** measurements repeat 128 complete GPU-resident tasks per CUDA graph, including training copies, and benefit from warm caches. Transfers, allocation, JIT, graph capture, startup and host energy are excluded. The target active window was 3 seconds; actual windows were 2.35–2.38 seconds because measured throughput differed from calibration. The cause was not measured.
- **Scorer provenance, resolved:** a development run overlapped a source edit adding the saved-IR parser. That run was replaced by a full execution of the unchanged final source. The retained generator run took 34.899 s; replay of the emitted 11,171,400-instruction text took 111.164 s. Source hashes, predictions, access counts and exact scores agree. No favorable runtime was selected for submission.
- **Report environment, resolved:** the system Python's package resolver could not install the requested Markdown version. The report renderer was run in a separate Python 3.11 environment with Markdown 3.8.2. This did not affect model or GPU measurements.

The most useful benchmark changes would be to freeze numeric/tape/area conventions, validate canonical dataset identities in the evaluator, and standardize full-task timing and idle-energy measurement boundaries. The submitted sources and raw evidence make these choices reviewable now; they do not establish organizer acceptance.

### Rule update observed before publication

Main advanced during the attempt to `1ede666`. Its README now calls the model scores theoretical and permits an A100 ISA of choice; `mnist/instructions.md` still names Triton or pyptx. The submission's Triton implementation satisfies either tool choice. Accuracy target, dataset and linked Dally model are unchanged. The request to “compile” the algorithm does not state whether an automatic v4-to-GPU compiler is required: this attempt provides a hand-written equivalent Triton implementation with numerical cross-checks, rather than an automatic compiler. Freeze that requirement if compilation tooling itself is intended to be part of the contest.
